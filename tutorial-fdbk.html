Tutorial: a feedback ripple, DN style

Build a 13 × 13 animated control in the sketch editor: rings that ripple out from the centre as a param turns up, inside a fixed frame. It's modelled on an FM synth's FDBK. About 10 minutes.

Inspired by the Elektron DN's screens. Not affiliated with Elektron.

value 0

0 Look before you draw

Sweep the slider above (or watch it play). The control has three parts, and how each part behaves decides how you build it:

The frame
Four diagonal corners. Never moves → linked objects.
Ripple 1
Grows from nothing at 0 to full size at 63, then stays → grows from its centre.
Ripples 2 and 3
Start again at 64 and 108 → more keys, each ring missing where it hasn't started yet.

Every shape is an octagon: flat 3-pixel ends and 45° sides, which is a "circle" at this size. Drawing octagons with clicks (not freehand) gets every pixel right.

The reference, every 4th value

Each step's picture shows what you should have after the step. Load this result puts that into the editor, to catch up or skip ahead.

1 Set up the cell

  1. Open the editor and click New.
  2. Set Cell to 13 × 13.
  3. Check the editor's title says v4 or later. If it doesn't, reload the page (⌘R).
  4. Set Frames to 32. The DN shows 32 different images for this control, one for every 4 values, so 32 frames is enough and 128 would waste memory.

2 Plan the keys

A key is a param value where you say exactly what the control looks like. You have 0 and 127; add four more:

  1. Click key 0, then + Key. Type 63 into the new key's box and press Enter.
  2. Repeat for 64, 99 and 108.

What they're for:

  • 0 → 63: ripple 1 grows.
  • 64 → 99: ripple 2 grows.
  • 108 → 127: ripple 3 grows.
  • 63/64 and 99/108 are pairs, so a new ring starts right where the last one stops.

3 Draw the frame (linked)

  1. Leave New shapes linked ticked: the frame goes on every key and stays still.
  2. Pick Line 2. Drag four short diagonals, one across each corner:
    • top-left: from (3,0) to (0,3)
    • top-right: (9,0) to (12,3)
    • bottom-left: (0,9) to (3,12)
    • bottom-right: (12,9) to (9,12)
    Coordinates are (column, row): the numbers along the top are columns, those down the left are rows. The line under the grid shows the pixel under your pointer, and while you drag it shows "from … to …".
  3. Your drag doesn't have to be neat: lines snap to exact 45°.

Rename objects in the right panel (Name) as you go, e.g. "frame TL". The list stays readable when you have ten of them.

4 Ripple 1: draw once, remove it at key 0

  1. Still linked: pick Poly 6. Click each of the 8 corners of the big octagon, going round. A little wobble while clicking is fine. The corners so far show under the grid. Click the first corner again to close it:
    (5,0) (7,0) (12,5) (12,7) (7,12) (5,12) (0,7) (0,5)
  2. Check Objects shows one new poly. If you got several, undo with ⌘Z and reload the editor: an older cached copy treated each click as a separate shape.
  3. It's on every key now. Click key 0, then click the ● next to the octagon in Objects. That removes it from key 0 only (and unlinks it).
  4. Check Comes / goes says grows from its centre. Sweep the preview: the ring grows from a dot.

Why remove instead of drawing it small at key 0? "Missing from a key" means "comes out of nothing" to the editor, and the in-between sizes are made for you.

5 Ripple 2: draw unlinked, paste forward

  1. Untick New shapes linked. Click key 99.
  2. With Poly, click the middle octagon's corners, then click the first again:
    (5,2) (7,2) (10,5) (10,7) (7,10) (5,10) (2,7) (2,5)
  3. ⌘C, click key 108, ⌘V, click key 127, ⌘V. Pasting into a key that lacks it adds the same object, so it stays put from 99 on.

It's missing from keys 0, 63 and 64, so it grows between 64 and 99.

6 Ripple 3

  1. Click key 127. With Poly, click the small octagon, then the first corner again:
    (5,4) (7,4) (8,5) (8,7) (7,8) (5,8) (4,7) (4,5)
  2. Done. Press ▶ Sweep in the preview.

7 Put it on the Rytm screen

  1. In the editor, set Name to ripple, then click Copy JSON.
  2. Paste it into your layout's "bitmaps".
  3. Add a frames element on the page where you want it, driven by your feedback param, e.g. P5 on the first page:
{ "type": "frames", "bmp": "ripple", "p": 5, "x": 88, "y": 42 }

Cost: 32 frames × 26 bytes = 832 B. Because the frames are plain bitmaps, the Rytm shows exactly what the editor previews.

Saving memory on bigger controls: every frame stores the whole cell, static parts included. If a control has a large part that never moves, draw that part with layout elements (line, box…) and make the cell cover only the moving part.

✓ What you used

  • Shape picker (Line, Poly) and click-to-place corners for exact pixels.
  • Linked objects for anything that stays still.
  • Keys placed where something starts or stops, including back-to-back pairs (63/64).
  • Missing from a key = comes out of nothing, with a "grows from its centre" style.
  • Copy / paste the same object into later keys, so it holds still.
