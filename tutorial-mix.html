Tutorial: an X/Y mix bar

Build a 19 × 13 two-way bar. The middle means an even mix; the fill grows toward X as the value goes down and toward Y as it goes up. It's modelled on an FM synth's MIX. About 10 minutes. You'll learn corner-to-corner rectangles, single pixels, fills, and putting keys exactly where the timing needs them.

Inspired by the Elektron DN's screens. Not affiliated with Elektron.

There are 15 different pictures in all: the fill moves one pixel every 9 values or so, 7 steps each way from the middle.

The reference, every 8th value

Each step's picture shows what you should have after the step. Load this result puts that into the editor, to catch up or skip ahead.

1 Set up the cell

  1. In the editor (title v9 or later), click New.
  2. Set Cell to 19 × 13.
  3. Set Frames to 128, one per value. Step 8 explains why, and what fewer frames cost you. You can change it at any time; the drawing stays the same.

2 Keys: both ends and two in the middle

You have 0 and 127. Add 63 and 64: click key 0, + Key, type the value, Enter.

Why two middle keys? The middle picture (just the centre line) should hold from 59 to 68, and each side should take exactly 9 values per pixel:

  • Toward X, the fill shrinks from key 0 to 63.
  • Toward Y, it grows from 64 to 127.

With a single middle key at 64, the X side is half a value late: 3 values come out wrong.

3 The letters (linked lines)

  1. Keep New shapes linked ticked. Pick Line 2.
  2. X: drag (1,0) → (5,4), then (5,0) → (1,4).
  3. Y: drag (13,0) → (15,2), then (17,0) → (15,2), then (15,2) → (15,4).

Watch the readout under the grid: it shows "from … to …" while you drag. Start and end exactly on the listed pixels; the three Y strokes meet at (15,2).

4 Two single pixels: the centre ticks

  1. Still on Line: click once on (9,6) and once on (9,12).

A click with the Line tool makes a one-pixel object. These two mark the centre above and below the track.

5 The track: a rectangle from corner to corner

  1. Pick Rect 5. Drag from (1,7) to (17,11). The rectangle spans your drag's two corners, so the path in between doesn't matter.
  2. In Selected object, set Corners to 1. That rounds the ends by cutting each corner pixel.

6 The fill: draw once, then unlink

  1. Tick New shapes filled (next to New shapes linked).
  2. With Rect, drag (2,8) → (9,10). That's the X-side fill, on every key for now.
  3. In Objects, click the fill's 🔗 to unlink it. From now on, edits change only the key you're on.

7 Move the fill's edge on each key

  1. Pick Edit E. Click the fill to see its two orange handles: top-left and bottom-right.
  2. Key 63: drag the top-left handle from (2,8) to (9,8). Only the centre column is left.
  3. Key 64: the same.
  4. Key 127: drag the top-left handle (2,8) → (9,8), then the bottom-right (9,10) → (16,10).
  5. Press ▶ Sweep.

Why it grows from the centre: between two keys that share an edge (column 9), that edge stays put and only the other one moves. A rectangle whose edges both change slides instead, keeping its width.

8 Pick a frame count

The editor shows 15 different pictures, but how many frames you store decides the timing and the memory. Same drawing, four frame counts:

FramesMemoryThe picture can change
1284992 Bat every value
642496 Bevery 2 values
321248 Bevery 4 values
16624 Bevery 8 values

Fewer frames means the picture changes on a coarser grid of values: with 16 frames, a change you keyed at value 5 shows up at 8. The pictures are all the same; only when they change moves, by a few values.

128 frames is wasteful: it stores 15 pictures over and over. A better format would store the 15 pictures plus a small value → picture table: about 585 + 128 bytes, and still exact. rmpUI's frames element can't do that yet. Worth adding if your controls are tight on memory; for now, 16 frames is a fine trade.

9 Put it on the Rytm screen

  1. In the editor, set Name to mix, then click Copy JSON.
  2. Paste it into your layout's "bitmaps".
  3. Add the element, driven by your mix param, for example here on the first page:
{ "type": "frames", "bmp": "mix", "p": 8, "x": 105, "y": 42 }

Use your own param number for "p".

✓ What you used

  • Rect by corner-to-corner drag, Corners for rounded ends, and filled.
  • A click with Line for single pixels.
  • Draw linked, then unlink: one object that starts the same on every key, then changes per key.
  • Edit handles to move just one edge per key; a shared edge stays fixed in the in-betweens.
  • Key timing: back-to-back middle keys (63/64) so both sides take the same number of values per step.
  • Frame count as a timing-versus-memory choice.
